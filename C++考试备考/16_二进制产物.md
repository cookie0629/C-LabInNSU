## 题目 / Вопрос

- **中文**：编译 C++ 代码时可以得到哪些二进制产物（如目标文件、静态库、动态库、可执行文件等）？  
- **俄文**：Какие бинарные артефакты можно получить при компиляции C++ кода?

C++ 的编译过程（从源码到程序）是一个多阶段的过程，每个阶段都可能产生特定的二进制文件。

以下是 C++ 开发中常见的四种二进制产物的中俄互译及详细说明：

------

### 1. 目标文件 (Object File / Объектный файл)

这是编译的中间产物。

(Это промежуточный продукт компиляции.)

- **中文**：
  - 当编译器处理一个 `.cpp` 源文件时，它会生成一个目标文件。
  - 它包含了该文件对应的**机器码 (Machine Code)** 和 **符号表 (Symbol Table)**。
  - 此时，代码中的外部函数调用（如调用其他文件的函数）还未被解析（地址是空的），因此它还不能运行。
- **Русский**：
  - Когда компилятор обрабатывает один исходный файл `.cpp`, он создает объектный файл.
  - Он содержит **машинный код (Machine Code)** и **таблицу символов (Symbol Table)** для этого файла.
  - На этом этапе вызовы внешних функций (например, функций из других файлов) еще не разрешены (адреса пустые), поэтому запустить его нельзя.
- **扩展名 (Расширения)**:
  - Windows (MSVC): `.obj`
  - Linux/Unix (GCC/Clang): `.o`

------

### 2. 静态库 (Static Library / Статическая библиотека)

这是目标文件的归档包。

(Это архив объектных файлов.)

- **中文**：
  - 它本质上就是把多个 `.o` 或 `.obj` 文件打包在一起（像 ZIP 压缩包一样，但不压缩）。
  - **链接机制**：当你链接静态库时，链接器会将库中被用到的代码**完整复制**到你的最终可执行文件中。
  - **优点**：发布方便（只有一个 exe）。**缺点**：可执行文件体积大，库更新需要重新编译程序。
- **Русский**：
  - По сути, это просто упаковка нескольких файлов `.o` или `.obj` вместе (как ZIP-архив, но без сжатия).
  - **Механизм линковки**: При линковке статической библиотеки компоновщик **полностью копирует** используемый код из библиотеки в ваш конечный исполняемый файл.
  - **Плюс**: Удобство распространения (один exe). **Минус**: Большой размер exe, для обновления библиотеки нужно перекомпилировать программу.
- **扩展名 (Расширения)**:
  - Windows: `.lib`
  - Linux/Unix: `.a` (Archive)

------

### 3. 动态库 (Dynamic Library / Динамическая библиотека)

也称为 共享库 (Shared Library)。

(Также известна как разделяемая библиотека.)

- **中文**：
  - 它也是目标文件的集合，但具有特殊的结构。
  - **链接机制**：链接时，可执行文件只记录了“我需要这个库”的**引用**，而没有复制实际代码。代码在程序**运行时 (Runtime)** 才被加载到内存。
  - **优点**：多个程序可以共享同一份内存中的库（节省内存），库可以独立更新。
- **Русский**：
  - Это тоже набор объектных файлов, но со специальной структурой.
  - **Механизм линковки**: При линковке в исполняемый файл записывается только **ссылка** «мне нужна эта библиотека», код не копируется. Код загружается в память только во время **выполнения (Runtime)**.
  - **Плюс**: Несколько программ могут использовать одну копию библиотеки в памяти (экономия памяти), библиотеку можно обновлять независимо.
- **扩展名 (Расширения)**:
  - Windows: `.dll` (Dynamic Link Library)
  - Linux: `.so` (Shared Object)
  - macOS: `.dylib`

------

### 4. 可执行文件 (Executable File / Исполняемый файл)

这是最终的成品。

(Это конечный продукт.)

- **中文**：
  - 经过**链接器 (Linker)** 处理后生成的文件。
  - 它必须包含一个 **入口点 (Entry Point)**（通常是 `main` 函数），操作系统可以直接加载并运行它。
  - 它可能包含静态链接进来的代码，并依赖系统中存在的动态库。
- **Русский**：
  - Файл, созданный после обработки **компоновщиком (Linker)**.
  - Он обязан содержать **точку входа (Entry Point)** (обычно функцию `main`), и операционная система может его загрузить и выполнить.
  - Он может содержать статически слинкованный код и зависеть от динамических библиотек, присутствующих в системе.
- **扩展名 (Расширения)**:
  - Windows: `.exe`
  - Linux/Unix: 通常没有扩展名 (通常有 `x` 权限位)，或者是 `.out`

------

### 总结对照表 (Сводная таблица)

| **产物 (Артефакт)** | **Windows** | **Linux** | **作用 (Роль)**                              |
| ------------------- | ----------- | --------- | -------------------------------------------- |
| **Object File**     | `.obj`      | `.o`      | 编译单元中间产物 (Промежуточный продукт)     |
| **Static Lib**      | `.lib`      | `.a`      | 编译期合并代码 (Копирование кода при сборке) |
| **Dynamic Lib**     | `.dll`      | `.so`     | 运行时加载代码 (Загрузка кода при запуске)   |
| **Executable**      | `.exe`      | (none)    | 最终程序 (Конечная программа)                |

注意 (Примечание):

在 Windows 上，.lib 文件有两种情况：

1. **静态库**：包含实际代码。

2. 导入库 (Import Library)：配合 .dll 使用，它不含代码，只包含“如何找到 DLL 中函数”的信息。

   (На Windows файлы .lib бывают двух типов: 1. Статическая библиотека (содержит код). 2. Библиотека импорта (для .dll, содержит только информацию о том, где найти функции).)

链接错误的本质是：**声明和定义的匹配失败**

### **关键要点：**

1. **未定义引用** = 有声明，无定义
2. **多重定义** = 一个符号有多个定义
3. **链接顺序很重要** = 被依赖的库放在后面
