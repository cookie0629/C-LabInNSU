## 题目 / Вопрос

- **中文**：在 C 和 C++ 中，有哪些实现错误处理的方式（如返回码、`errno`、异常等）？  
- **俄文**: Какие подходы к реализации обработки ошибок в C и C++ вы знаете?

这是在 C 和 C++ 中常见的错误处理方式，分为 **C 语言风格（C & C++ 通用）** 和 **C++ 现代风格**。

Вот распространенные подходы к обработке ошибок в C и C++, разделенные на **стиль C (общий для C и C++)** и **современный стиль C++**.

------

### 1. C 语言风格 / Стиль C (Legacy & Low-level)

这些方法在 C 语言中是标准，在 C++ 中（尤其是系统编程或嵌入式开发）仍然非常常用。

Эти методы являются стандартом в C и широко используются в C++ (особенно в системном программировании).

#### **A. 返回码 / Коды возврата (Return Codes)**

- **中文**: 函数返回一个整数或枚举值来表示成功或失败。通常 `0` 表示成功，非零值表示特定的错误类型。
- **Русский**: Функция возвращает целое число или значение перечисления, указывающее на успех или неудачу. Обычно `0` означает успех, а ненулевое значение — конкретный тип ошибки.
  - *Example:* `int status = perform_task(); if (status != 0) { /* handle error */ }`

#### **B. 全局变量 / Глобальная переменная (`errno`)**

- **中文**: 许多标准 C 库函数（如文件 I/O、数学函数）在出错时会设置全局变量 `errno`。函数通常返回 `-1` 或 `NULL` 作为信号，然后调用者检查 `errno` 获取具体原因。
- **Русский**: Многие функции стандартной библиотеки C (например, файловый ввод-вывод) устанавливают глобальную переменную `errno` при ошибке. Функция возвращает `-1` или `NULL` как сигнал, а вызывающий код проверяет `errno` для выяснения причины.

#### **C. 输出参数 / Выходные параметры (Output Parameters)**

- **中文**: 函数的返回值用于指示状态（成功/失败），而实际的计算结果通过指针参数传出。
- **Русский**: Возвращаемое значение функции указывает на статус (успех/неудача), а фактический результат вычисления передается через параметры-указатели.
  - *Example:* `bool get_value(int* out_result);`

#### **D. `goto` 跳转 / Переход `goto`**

- **中文**: 在 C 语言中，`goto` 常用于集中处理资源清理（如关闭文件、释放内存），避免重复代码。
- **Русский**: В C `goto` часто используется для централизованной очистки ресурсов (закрытие файлов, освобождение памяти), чтобы избежать дублирования кода.

------

### 2. C++ 专属风格 / Специфично для C++

#### **A. 异常 / Исключения (Exceptions)**

- **中文**: 使用 `try-catch` 块。当错误发生时，使用 `throw` 抛出异常对象。这是 C++ 标准库的主要错误处理方式。
  - **优点**: 错误处理逻辑与业务逻辑分离；自动调用析构函数（RAII）。
  - **缺点**: 有运行时开销；在某些嵌入式或实时系统中被禁用。
- **Русский**: Использование блоков `try-catch`. При возникновении ошибки выбрасывается объект исключения через `throw`. Это основной способ обработки ошибок в стандартной библиотеке C++.
  - **Плюсы**: Отделение обработки ошибок от бизнес-логики; автоматический вызов деструкторов (RAII).
  - **Минусы**: Накладные расходы во время выполнения; иногда отключается в embedded/real-time системах.

#### **B. `std::optional` (C++17)**

- **中文**: 用于函数可能无法返回有效值的情况。它要么包含一个值，要么包含 `std::nullopt`（空）。这是一种更语义化、更安全的替代 `NULL` 指针或特定错误码的方式。
- **Русский**: Используется, когда функция может не вернуть валидное значение. Содержит либо значение, либо `std::nullopt` (пусто). Это более семантическая и безопасная альтернатива указателям `NULL` или спец-кодам.

#### **C. `std::expected` (C++23)**

- **中文**: 它是 `std::optional` 的进化版。它要么包含预期的结果值（Expected），要么包含错误信息（Unexpected）。这类似于 Rust 语言中的 `Result` 类型。
- **Русский**: Эволюция `std::optional`. Содержит либо ожидаемое значение (Expected), либо информацию об ошибке (Unexpected). Это похоже на тип `Result` в языке Rust.

#### **D. `std::system_error` (C++11)**

- **中文**: 这是一个异常类，专门用于封装底层的 `errno` 或操作系统错误码，将 C 风格错误转化为 C++ 异常。
- **Русский**: Класс исключений, предназначенный для обертки низкоуровневых `errno` или кодов ошибок ОС, преобразуя ошибки стиля C в исключения C++.

### 总结比较 / Сводная таблица

| **方法 / Метод**  | **语言 / Язык** | **适用场景 / Сценарий использования**                        |
| ----------------- | --------------- | ------------------------------------------------------------ |
| **Return Codes**  | C, C++          | 高性能要求，系统调用，C 接口 / Высокая производительность, системные вызовы, C-API |
| **errno**         | C, C++          | 遗留代码，Unix 系统接口 / Устаревший код, API Unix-систем    |
| **Exceptions**    | C++             | 面向对象设计，大多数应用程序 / ООП, большинство приложений   |
| **std::optional** | C++ (17+)       | 值可能不存在（非错误） / Значение может отсутствовать (не ошибка) |
| **std::expected** | C++ (23+)       | 既需要结果又需要错误详情 / Требуется и результат, и детали ошибки |
