## 题目 / Вопрос

- **中文**：你知道 C++ 中有哪些互斥量（mutex）的类型？每一种互斥量主要用来解决什么问题？  
- **俄文**: Какие виды мьютексов в C++ вы знаете? Какие проблемы решает каждый из видов мьютексов?

C++ 标准库（`<mutex>` 和 `<shared_mutex>`）提供了几种不同类型的互斥量，专为不同的并发场景设计。

以下是中俄互译的详细分类与用途解析：

------

### 1. `std::mutex` (基本的互斥量 / Базовый мьютекс)

- **特点 (Характеристика)**:
  - 最基础、开销最小的互斥量。
  - **不可递归**：如果同一个线程试图对它加锁两次，会产生**死锁 (Deadlock)** 或未定义行为。
  - (*Базовый мьютекс с минимальными накладными расходами. **Не рекурсивный**: повторная попытка захвата тем же потоком приведет к **дедлоку** или неопределенному поведению.*)
- **解决的问题 (Решаемая проблема)**:
  - 保护**临界区 (Critical Section)**，确保同一时间只有一个线程能访问共享数据。适用于绝大多数简单的同步场景。
  - (*Защита **критической секции**, гарантирующая, что только один поток имеет доступ к общим данным. Подходит для большинства простых сценариев синхронизации.*)

------

### 2. `std::recursive_mutex` (递归互斥量 / Рекурсивный мьютекс)

- **特点 (Характеристика)**:
  - 允许**同一个线程**多次获取同一把锁（内部有一个计数器）。
  - 解锁次数必须与加锁次数相同，锁才会被释放。
  - (*Позволяет **одному и тому же потоку** захватывать мьютекс многократно (использует внутренний счетчик). Мьютекс освобождается только тогда, когда количество разблокировок совпадает с количеством блокировок.*)
- **解决的问题 (Решаемая проблема)**:
  - 解决**递归函数**或**复杂的类方法相互调用**时的死锁问题。
  - *示例*：函数 A 锁住了 mutex，然后调用函数 B，函数 B 也试图锁住同一个 mutex。如果是普通 mutex 会死锁，递归 mutex 则允许。
  - (*Решает проблему дедлока в **рекурсивных функциях** или при **взаимных вызовах методов класса**. \*Пример\*: Функция A захватывает мьютекс и вызывает B, которая тоже пытается его захватить.*)

------

### 3. `std::timed_mutex` (带超时的互斥量 / Мьютекс с таймаутом)

- **特点 (Характеристика)**:
  - 除了基本的 `lock()`，还提供了 `try_lock_for()` 和 `try_lock_until()`。
  - (*В дополнение к `lock()`, предоставляет методы `try_lock_for()` и `try_lock_until()`.*)
- **解决的问题 (Решаемая проблема)**:
  - 防止线程**无限期阻塞 (Indefinite Blocking)**。
  - 如果一定时间内拿不到锁，线程可以选择放弃操作、记录日志或执行其他任务，而不是一直卡死在那里。
  - (*Предотвращает **бесконечную блокировку** потока. Если мьютекс не удается захватить за определенное время, поток может отказаться от операции или выполнить другую задачу, вместо того чтобы зависнуть.*)

------

### 4. `std::shared_mutex` (共享互斥量 / Разделяемый мьютекс)

- **引入版本**: C++17 (C++14 中有 `std::shared_timed_mutex`)
- **特点 (Характеристика)**:
  - 也被称为 **读写锁 (Reader-Writer Lock)**。
  - 支持两种锁定模式：
    1. **共享锁 (Shared Lock)**: 多个线程可以同时持有（用于读）。
    2. **独占锁 (Exclusive Lock)**: 只有一个线程可以持有（用于写）。
  - (*Также известен как **Reader-Writer Lock**. Поддерживает два режима: 1. **Shared Lock**: несколько потоков могут держать одновременно (для чтения). 2. **Exclusive Lock**: только один поток может держать (для записи).* )
- **解决的问题 (Решаемая проблема)**:
  - 优化 **“读多写少”** 的场景。
  - 如果有 10 个线程只读数据，1 个线程写数据，普通 mutex 会让那 10 个读者排队；而 `shared_mutex` 允许 10 个读者同时读取，大大提高了并发性能。
  - (*Оптимизация сценариев **«много чтений, мало записи»**. Обычный мьютекс заставит читателей ждать в очереди, а `shared_mutex` позволяет им читать данные параллельно, повышая производительность.*)

------

### 最佳实践 (Best Practice / Лучшие практики)

永远不要手动调用 lock() 和 unlock()！请使用 RAII 包装器：

(Никогда не вызывайте lock() и unlock() вручную! Используйте RAII-обертки:)

1. **`std::lock_guard`**: 简单、开销极小，作用域结束自动释放。
2. **`std::unique_lock`**: 灵活，支持手动 `unlock`、延迟加锁、条件变量。
3. **`std::shared_lock`**: 配合 `shared_mutex` 使用，获取读锁。

C++

```c
#include <shared_mutex>
#include <mutex>

std::shared_mutex rw_lock;
int data = 0;

// Reader (读者)
int readData() {
    // 申请共享锁 (读锁)
    // Запрос разделяемой блокировки (на чтение)
    std::shared_lock<std::shared_mutex> lock(rw_lock);
    return data;
}

// Writer (写者)
void writeData(int value) {
    // 申请独占锁 (写锁)
    // Запрос эксклюзивной блокировки (на запись)
    std::unique_lock<std::shared_mutex> lock(rw_lock);
    data = value;
}
```

核心思想

- **获取即初始化**：资源在对象的构造函数中被获取（分配/打开），此时资源就与对象绑定了。
- **生命周期管理**：资源的使用权随对象生命周期而存在。
- **自动释放**：当对象超出作用域时，其析构函数被自动调用，在析构函数中释放资源
