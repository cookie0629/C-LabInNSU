## 题目 / Вопрос

- **中文**：在 C++ 中，什么是“数据竞争”（data race）？如何避免数据竞争？  
- **俄文**: Что такое гонки данных в C++? Как избежать гонки данных?

**数据竞争 (Data Race)** 是 C++ 多线程编程中最严重、最常见的问题之一。如果你的程序包含数据竞争，它就包含了**未定义行为 (Undefined Behavior)**。

**Гонка данных (Data Race)** — это одна из самых серьезных и распространенных проблем в многопоточном программировании на C++. Если ваша программа содержит гонку данных, она содержит **неопределенное поведение (Undefined Behavior)**.

------

### 1. 什么是数据竞争？/ Что такое гонка данных?

根据 C++ 标准，当满足以下所有三个条件时，就会发生数据竞争：

Согласно стандарту C++, гонка данных возникает, когда выполняются все три условия:

1. **并发访问 (Concurrency)**: 两个或多个线程同时访问同一个内存位置。
   - *RU*: Два или более потока одновременно обращаются к одной и той же области памяти.
2. **写操作 (Write)**: 其中**至少有一个**访问是写操作（修改数据）。
   - *RU*: **Хотя бы одно** из этих обращений является записью (изменением данных).
3. **无同步 (No Synchronization)**: 线程之间没有使用任何同步机制（如互斥锁或原子操作）来确立先后顺序。
   - *RU*: Между потоками не используется механизм синхронизации (например, мьютексы или атомики) для установления порядка выполнения.

> 警告: 数据竞争不仅仅意味着“结果计算错误”。编译器可能会进行激进的优化，导致程序崩溃、死循环或产生完全随机的结果。
>
> Внимание: Гонка данных означает не просто «неверный результат вычислений». Компилятор может выполнять агрессивную оптимизацию, что приведет к краху программы, бесконечному циклу или абсолютно случайным результатам.

------

### 2. 如何避免数据竞争？/ Как избежать гонки данных?

主要有三种策略：

Существует три основные стратегии:

#### **A. 使用互斥锁 / Использование мьютексов (`std::mutex`)**

- **中文**: 使用 `std::mutex` 来保护共享数据。在访问数据前加锁 (`lock`)，访问后解锁 (`unlock`)。
  - *最佳实践*: 使用 RAII 包装器 `std::lock_guard` 或 `std::unique_lock`，防止因忘记解锁或异常导致的死锁。
- **Русский**: Используйте `std::mutex` для защиты общих данных. Блокируйте (`lock`) перед доступом и разблокируйте (`unlock`) после.
  - *Лучшая практика*: Используйте RAII-обертки `std::lock_guard` или `std::unique_lock`, чтобы предотвратить взаимную блокировку из-за забытого `unlock` или исключения.

#### **B. 使用原子操作 / Атомарные операции (`std::atomic`)**

- **中文**: 对于简单的基本类型（如整数、布尔值、指针），使用 `std::atomic<T>`。原子操作保证了单个指令的不可分割性，不需要锁。
- **Русский**: Для простых типов (целые числа, булевы значения, указатели) используйте `std::atomic<T>`. Атомарные операции гарантируют неделимость одной инструкции и не требуют мьютексов.

#### **C. 消除共享状态 / Устранение общего состояния**

- **中文**: 既然共享会导致竞争，那就不要共享。使用 `thread_local` 变量，或者按值传递数据，让每个线程拥有自己的副本。
- **Русский**: Раз общее состояние вызывает гонку, избавьтесь от него. Используйте `thread_local` переменные или передавайте данные по значению, чтобы у каждого потока была своя копия.

### 代码示例 / Пример кода

这个例子展示了一个典型的计数器竞争，以及如何修复它。

Этот пример показывает типичную гонку в счетчике и способы её исправления.

C++

```c
#include <iostream>
#include <thread>
#include <vector>
#include <mutex>
#include <atomic>

// 1. The Problem: Data Race (Undefined Behavior)
// 问题：数据竞争（普通 int 被多线程同时修改）
int shared_counter = 0; 

void unsafe_increment() {
    for (int i = 0; i < 1000; ++i) {
        // Read -> Modify -> Write is NOT atomic!
        shared_counter++; 
    }
}

// 2. Solution A: Mutex
// 方案 A：互斥锁
std::mutex mtx;
int safe_counter_mutex = 0;

void safe_increment_mutex() {
    for (int i = 0; i < 1000; ++i) {
        std::lock_guard<std::mutex> lock(mtx);
        safe_counter_mutex++;
    }
}

// 3. Solution B: Atomics (Fastest for counters)
// 方案 B：原子操作（计数器场景最快）
std::atomic<int> safe_counter_atomic{0};

void safe_increment_atomic() {
    for (int i = 0; i < 1000; ++i) {
        safe_counter_atomic++; // Atomic fetch_add
    }
}

int main() {
    std::vector<std::thread> threads;
    
    // Launch 10 threads using atomic solution
    for(int i = 0; i < 10; ++i) {
        threads.emplace_back(safe_increment_atomic);
    }

    for(auto& t : threads) {
        t.join();
    }

    std::cout << "Final Atomic Count: " << safe_counter_atomic << std::endl;
    // Expected: 10000. Without atomic/mutex, it would be random < 10000.
    // Ожидается: 10000. Без atomic/mutex число было бы случайным < 10000.

    return 0;
}
```
