## 题目 / Вопрос

- **中文**：在 C++ 中，从源代码到最终程序经历哪些转换阶段？什么是“翻译单元”（translation unit）？  
- **俄文**: Какие этапы трансформации программного кода определены в C++? Что такое юнит трансляции?

在 C++ 中，从源代码到可执行程序的构建过程通常被称为**编译管线（Compilation Pipeline）**。这不仅仅是一步操作，而是四个截然不同的阶段。

В C++ процесс создания исполняемой программы из исходного кода обычно называют **конвейером компиляции (Compilation Pipeline)**. Это не одно действие, а четыре различных этапа.

### 1. 转换阶段 / Этапы трансформации

#### **Phase 1: 预处理 / Препроцессинг (Preprocessing)**

- **中文**: 处理以 `#` 开头的指令（如 `#include`, `#define`）。
  - 预处理器将头文件的内容**复制粘贴**到源文件中，替换宏定义，并删除注释。此时的结果是一个纯文本文件。
- **Русский**: Обработка директив, начинающихся с `#` (например, `#include`, `#define`).
  - Препроцессор **копирует и вставляет** содержимое заголовочных файлов в исходный файл, подставляет макросы и удаляет комментарии. Результат — чистый текстовый файл.

#### **Phase 2: 编译 / Компиляция (Compilation)**

- **中文**: 编译器将预处理后的代码翻译成**汇编语言（Assembly Language）**。
  - 这是进行语法检查和代码优化的阶段。如果代码有语法错误，会在这一步报错。
- **Русский**: Компилятор переводит код после препроцессинга на **язык ассемблера**.
  - Это этап проверки синтаксиса и оптимизации кода. Если есть синтаксические ошибки, они будут выявлены здесь.

#### **Phase 3: 汇编 / Ассемблирование (Assembly)**

- **中文**: 汇编器将汇编代码转换为机器可以直接执行的**机器码**，生成**目标文件（Object File, .o 或 .obj）**。
  - 此时的文件是二进制格式，但还不可执行，因为函数调用（如 `printf` 或其他文件的函数）的地址还没确定。
- **Русский**: Ассемблер преобразует ассемблерный код в **машинный код**, который может быть выполнен процессором, создавая **объектный файл (.o или .obj)**.
  - Файл уже в бинарном формате, но еще не исполняемый, так как адреса вызовов функций (например, `printf` или функций из других файлов) еще не определены.

#### **Phase 4: 链接 / Компоновка (Linking)**

- **中文**: 链接器将所有的目标文件（`.o`）和所需的库文件（`.lib`, `.a`）合并，解析符号引用，生成最终的**可执行文件（Executable）**。
  - 如果函数声明了但未定义，会报“Linker Error” (如 LNK2019)。
- **Русский**: Компоновщик (линкер) объединяет все объектные файлы (`.o`) и необходимые библиотеки (`.lib`, `.a`), разрешает ссылки на символы и создает итоговый **исполняемый файл**.
  - Если функция объявлена, но не определена, возникнет «Ошибка линковки» (например, LNK2019).

### 2. 什么是“翻译单元”？/ Что такое "Юнит трансляции"?

中文定义:

翻译单元（Translation Unit, TU）是编译器在预处理之后、编译之前所看到的输入内容。

- **公式**: `翻译单元 = 源文件 (.cpp) + 包含的所有头文件 (.h) - 条件编译排除的代码 (#ifdef)`。
- **关键点**: 编译器是以翻译单元为单位工作的。每个 `.cpp` 文件（加上它包含的头文件）都是独立编译的，互不知道对方的存在，直到链接阶段。

Русское определение:

Единица трансляции (Translation Unit, TU) — это входные данные, которые видит компилятор после препроцессинга, но перед компиляцией.

- **Формула**: `Единица трансляции = Исходный файл (.cpp) + Все включенные заголовки (.h) - Исключенный код (#ifdef)`.
- **Ключевой момент**: Компилятор работает с единицами трансляции. Каждый `.cpp` файл (вместе с его заголовками) компилируется независимо, они "не знают" о существовании друг друга до этапа линковки.

Plaintext

```
Source (.cpp) + Headers (.h)
       |
       v
[ Preprocessor / Препроцессор ] -> Removes comments, expands #includes
       |
       v
Translation Unit (Full Code)  <-- THIS IS IT / ВОТ ОНО
       |
       v
[ Compiler / Компилятор ]
       |
       v
Object File (.o / .obj)
```
