## 题目 / Вопрос

- **中文**：在 C++ 中，什么是“模板”？有哪些种类的模板？在模板的定义与实例化时分别有哪些要求？这些要求如何与“鸭子类型（duck typing）”惯用法相关联？  
- **俄文**: Что такое шаблон в C++? Какие виды шаблонов бывают? Какие требования предъявляются к шаблону при определении и инстанциации и как с ними связана идиома утиной типизации?

**模板（Templates）** 是 C++ 泛型编程（Generic Programming）的基石。

**Шаблоны (Templates)** — это краеугольный камень обобщенного программирования (Generic Programming) в C++.

------

### 1. 什么是模板？ / Что такое шаблон?

- **中文**:
  - 模板不是真正的代码，而是**生成代码的蓝图（Blueprint）**或模具。
  - 编译器在编译时，根据你提供的具体类型（如 `int`, `float`, `MyClass`），利用模板自动生成具体的类或函数代码。
- **Русский**:
  - Шаблон — это не настоящий код, а **чертеж (Blueprint)** или форма для генерации кода.
  - Во время компиляции, на основе предоставленных вами конкретных типов (например, `int`, `float`, `MyClass`), компилятор автоматически генерирует конкретный код класса или функции.

------

### 2. 模板的种类 / Виды шаблонов

主要有两种（C++14/17 引入了更多，但这是基础）：

Основные два вида (в C++14/17 добавились другие, но это база):

1. **函数模板 (Function Templates)**:
   - 定义通用的算法。
   - *例*: `std::sort`, `std::max`.
2. **类模板 (Class Templates)**:
   - 定义通用的数据结构。
   - *例*: `std::vector<T>`, `std::map<K, V>`.

(注：还有变量模板 Variable Templates 和 别名模板 Alias Templates)

(Примечание: существуют также шаблоны переменных и шаблоны псевдонимов)

------

### 3. 定义与实例化的要求 / Требования к определению и инстанциации

这是理解模板运作机制的关键，分为两个阶段：

Это ключ к пониманию механизма работы шаблонов, который делится на два этапа:

#### **A. 定义阶段 (Definition Phase)**

- **要求**: 模板内部的语法必须正确（括号匹配、关键字正确）。
- **检查**: 编译器只进行**最基本的语法检查**。它不检查类型 `T` 是否支持模板中使用的操作（例如 `T + T`）。
- **Русский**: Синтаксис внутри шаблона должен быть верным. Компилятор выполняет только **базовую проверку синтаксиса**. Он не проверяет, поддерживает ли тип `T` операции (например, `T + T`).

#### **B. 实例化阶段 (Instantiation Phase)**

- **要求**: 当你真正使用模板（如 `func<int>()`）时，编译器将 `int` 代入 `T`。此时，类型 `int` 必须支持模板中调用的**所有操作**。
- **检查**: 如果模板代码里写了 `x.draw()`，而你传入的 `int` 没有 `draw()` 方法，编译器会在这个阶段报错。
- **Русский**: Когда вы реально используете шаблон (например, `func<int>()`), компилятор подставляет `int` вместо `T`. В этот момент тип `int` должен поддерживать **все операции**, используемые в шаблоне. Если в коде шаблона есть `x.draw()`, а у `int` нет метода `draw()`, ошибка возникнет именно здесь.

------

### 4. 与“鸭子类型”的关联 / Связь с «Утиной типизацией»

C++ 模板实现了**编译期鸭子类型 (Compile-time Duck Typing)**。

Шаблоны C++ реализуют **утиную типизацию времени компиляции (Compile-time Duck Typing)**.

> Duck Typing 谚语: "如果它走起路来像鸭子，叫起来像鸭子，那它就是鸭子。"
>
> Пословица: "Если нечто ходит как утка и крякает как утка, то это утка".

- **传统面向对象 (Java/C#)**:
  - 你需要**显式继承**某个接口（如 `class Duck : public IDuck`），编译器才允许你调用 `quack()`。这是**基于名义的 (Nominal)**。
- **C++ 模板**:
  - 模板**不在乎**类型 `T` 继承自谁。
  - 模板只在乎：**类型 `T` 里面有没有 `quack()` 这个函数？**
  - 如果有，编译通过；如果没有，编译失败。
  - 这就是**隐式接口 (Implicit Interface)**。

**代码示例 / Пример кода**:

C++

```c
#include <iostream>

// The Template (The Duck Test)
// 模板：它只关心 T 是否能调用 quack()
// Шаблон: Ему важно только, можно ли вызвать quack() у T
template <typename T>
void makeItQuack(T& t) {
    t.quack(); // The Requirement / Требование
}

class Duck {
public:
    void quack() { std::cout << "Quack!" << std::endl; }
};

class Person {
public:
    // Person doesn't inherit from Duck, but acts like one!
    // Человек не наследует от Утки, но ведет себя так же!
    void quack() { std::cout << "I'm imitating a duck!" << std::endl; }
};

int main() {
    Duck d;
    Person p;

    // Both work because both satisfy the "Duck Typing" requirement
    // Оба работают, так как оба удовлетворяют требованию «Утиной типизации»
    makeItQuack(d); 
    makeItQuack(p); 

    return 0;
}
```

### 总结 / Итог

C++ 模板不要求类型具有特定的**血统**（继承关系），只要求类型具备特定的**行为**（能通过语法检查）。这就是为什么它被称为“静态鸭子类型”。

Шаблоны C++ не требуют от типов определенной **родословной** (наследования), они требуют только определенного **поведения** (чтобы пройти синтаксическую проверку). Именно поэтому это называется «статической утиной типизацией».
