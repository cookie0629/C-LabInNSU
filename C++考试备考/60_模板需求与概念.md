## 题目 / Вопрос

- **中文**：什么是“模板需求列表”（requires 子句、约束列表）？“概念（concepts）”为何被引入语言，它们是为了解决什么问题？  
- **俄文**: Что такое список требований шаблона? Как и для чего в язык было введено понятие «концептов»?

**概念 (Concepts)** 和 **约束 (Constraints)** 是 C++20 引入的最具革命性的特性之一，旨在解决模板编程（泛型编程）中长期存在的“报错地狱”和接口不清晰的问题。

**Концепты (Concepts)** и **ограничения (Constraints)** — это одни из самых революционных нововведений C++20. Они призваны решить давние проблемы шаблонного (обобщенного) программирования: «ад ошибок» и неясность интерфейсов.

------

### 1. 什么是 `requires` 子句（约束列表）？ / Что такое `requires` clause?

- **中文**:
  - `requires` 关键字用于在模板定义中引入**约束 (Constraints)**。
  - 它是一个**编译期布尔表达式**。只有当传入的模板参数满足该条件（即表达式求值为 `true`）时，模板才会被实例化。如果不满足，编译器会直接忽略该模板（而不是报错说模板内部代码出错），或者在没有其他匹配项时给出清晰的错误提示。
- **Русский**:
  - Ключевое слово `requires` используется для введения **ограничений (Constraints)** в определение шаблона.
  - Это **булево выражение времени компиляции**. Шаблон инстанцируется только в том случае, если переданные аргументы удовлетворяют условию (выражение истинно). В противном случае компилятор игнорирует шаблон (не выдавая ошибку внутри кода шаблона) или выдает четкую ошибку, если нет других совпадений.

------

### 2. 什么是“概念” (Concepts)？ / Что такое «Концепты»?

- **中文**:
  - 概念是**具名的约束集合**（Named set of constraints）。
  - 你可以把它想象成编译期的“接口”（Interface）。比如，你可以定义一个概念叫 `Sortable`，要求类型必须支持 `<` 比较和交换操作。
  - 标准库已经提供了一堆预定义概念，如 `std::integral` (整型), `std::copyable` (可拷贝), `std::ranges::range` (区间)。
- **Русский**:
  - Концепт — это **именованный набор ограничений**.
  - Можно представить это как «интерфейс» времени компиляции. Например, можно определить концепт `Sortable`, требующий от типа поддержки сравнения `<` и операции обмена (swap).
  - Стандартная библиотека предоставляет множество готовых концептов: `std::integral` (целочисленный), `std::copyable` (копируемый), `std::ranges::range` (диапазон).

------

### 3. 为什么要引入它们？解决什么问题？ / Зачем они введены? Какую проблему решают?

在此之前，C++ 使用 SFINAE (`enable_if`) 技术，这非常晦涩难懂。Concepts 解决了三大痛点：

До этого C++ использовал технику SFINAE (`enable_if`), которая была сложной и запутанной. Концепты решают три главные проблемы:

#### **A. 恐怖的错误信息 / Ужасные сообщения об ошибках**

- **Problem**: 在 C++20 之前，如果你把一个 `std::list` 传给需要随机访问迭代器的 `std::sort`，编译器会深入到 `std::sort` 内部实现，报出几百行看不懂的错误（如“`operator-` 未定义”）。
- **Solution**: 使用 Concept，编译器会直接说：“错误：`std::list` 不满足 `RandomAccessIterator` 概念”。
- **RU**: Раньше, передав `std::list` в `std::sort`, вы получали сотни строк ошибок из недр STL. С концептами компилятор просто скажет: "Ошибка: `std::list` не удовлетворяет концепту `RandomAccessIterator`".

#### **B. 明确的接口定义 / Четкое определение интерфейса**

- **Problem**:以前模板是“鸭子类型”（Duck Typing）——只有在实例化时才知道能不能用。代码很难读懂对 `T` 的要求。
- **Solution**: 在函数签名中显式写出 `template<Sortable T>`，相当于文档化了代码要求。
- **RU**: Раньше шаблоны использовали "утиную типизацию" — требования к `T` были неявными. Теперь подпись `template<Sortable T>` служит документацией.

#### **C. 简化重载 / Упрощение перегрузки**

- **Problem**: 编写针对不同类型的重载模板函数极其复杂。
- **Solution**: 基于 Concept 的重载非常直观。
- **RU**: Написание перегрузок шаблонов для разных типов стало интуитивно понятным.

### 代码示例 / Пример кода

C++

```c
#include <iostream>
#include <concepts> // C++20 header

// 1. Defining a Concept (Custom Interface)
// 定义一个概念：要求类型 T 必须支持加法操作
// Определение концепта: Тип T должен поддерживать сложение
template <typename T>
concept Addable = requires(T a, T b) {
    { a + b } -> std::convertible_to<T>; // 必须能相加，且结果可转换为 T
};

// 2. Using 'requires' clause
// 使用 requires 子句
template <typename T>
requires Addable<T>  // Constraint: T must satisfy Addable
T add(T a, T b) {
    return a + b;
}

// 3. Abbreviated Syntax (Syntactic Sugar)
// 简写语法 (即使这本质上是模板，看起来像普通函数)
// Сокращенный синтаксис
void print_int(std::integral auto i) {
    std::cout << "Integer: " << i << std::endl;
}

int main() {
    add(1, 2);       // ✅ OK: int is Addable
    add(1.5, 2.5);   // ✅ OK: double is Addable
    
    // add("Hello", "World"); 
    // ❌ Error: "const char*" does not satisfy 'Addable'
    // 错误信息非常清晰，直接指出不满足约束
    
    print_int(10);   // ✅ OK
    // print_int(3.14); // ❌ Error: double is not integral

    return 0;
}
```
