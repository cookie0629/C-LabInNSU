## 题目 / Вопрос

- **中文**：表达式 `delete` / `delete[]` 是如何工作的？  
- **俄文**：Как работает выражение `delete/delete[]`?

这是一个关于 C++ 内存管理机制的核心问题。理解这个过程对于防止内存泄漏和程序崩溃至关重要。

`delete` 和 `delete[]` 的工作流程都包含 **两个明确的步骤**，但它们处理对象数量的方式不同。

以下是中俄互译的详细解答：

------

### 一、 两个核心步骤 (Два основных шага)

无论是 delete 还是 delete[]，它们执行的操作顺序都是固定的：先清理对象，再释放内存。

(Будь то delete или delete[], порядок выполнения фиксирован: сначала очистка объекта, затем освобождение памяти.)

#### 1. 调用析构函数 (Вызов деструктора)

这是与 C 语言 free() 最大的区别。

(Это главное отличие от free() в языке C.)

- **`delete ptr`**:
  - **中文**：编译器生成代码，调用 `ptr` 指向的**单个**对象的析构函数 (`ptr->~T()`)。
  - **Русский**: Компилятор генерирует код для вызова деструктора **одного** объекта, на который указывает `ptr` (`ptr->~T()`).
- **`delete[] ptr`**:
  - **中文**：编译器生成代码，遍历数组中的**所有**元素，并**逆序**（从最后一个到第一个）调用它们的析构函数。
  - **Русский**: Компилятор генерирует код, который проходит по **всем** элементам массива и вызывает их деструкторы в **обратном порядке** (от последнего к первому).

#### 2. 释放内存 (Освобождение памяти)

析构函数执行完毕后，内存不再包含有效对象，变成“裸内存”。

(После выполнения деструктора память больше не содержит валидных объектов и становится «сырой памятью».)

- **`delete ptr`**:
  - **中文**：调用 `operator delete(void* ptr)` 函数，将内存归还给堆（Heap）。
  - **Русский**: Вызывает функцию `operator delete(void* ptr)`, возвращая память в кучу (Heap).
- **`delete[] ptr`**:
  - **中文**：调用 `operator delete[](void* ptr)` 函数。
  - **Русский**: Вызывает функцию `operator delete[](void* ptr)`.

------

### 二、 `delete[]` 如何知道要释放多少个元素？ (Откуда `delete[]` знает, сколько элементов удалять?)

这是一个经典的面试题。如果不告诉 delete[] 数组的大小，它怎么知道要调用 10 次析构函数还是 100 次？

(Это классический вопрос на собеседовании. Если не сообщить delete[] размер массива, как он узнает, нужно ли вызвать деструктор 10 раз или 100?)

- 中文解释：

  通常（依赖于编译器实现），当你调用 new Type[N] 时，编译器会在返回给你的指针地址之前，额外分配一小块内存（通常是 4 或 8 字节）。这块区域被称为 "Cookie" 或 "Overhead"，里面存储了数组的大小 $N$。

  当你调用 delete[] p 时，系统会悄悄地“回看”指针前面的内存，读取这个数字，从而知道需要循环调用多少次析构函数。

- Русское объяснение：

  Обычно (зависит от реализации компилятора), когда вы вызываете new Type[N], компилятор выделяет небольшой дополнительный блок памяти (обычно 4 или 8 байт) перед адресом, который возвращается вам. Эта область называется "Cookie" или "Overhead", и в ней хранится размер массива $N$.

  Когда вы вызываете delete[] p, система незаметно «заглядывает» в память перед указателем, считывает это число и понимает, сколько раз нужно вызвать деструктор в цикле.

------

### 三、 混用的后果 (Последствия смешивания)

如果 new 和 delete 不匹配使用，会导致 未定义行为 (Undefined Behavior)。

(Если new и delete не совпадают, это приводит к неопределенному поведению (UB).)

| **分配 (Allocation)** | **释放 (Deallocation)** | **后果 (Последствие)**                                       |
| --------------------- | ----------------------- | ------------------------------------------------------------ |
| `new T`               | `delete[] p`            | **Crash / UB**. 程序试图读取不存在的 "Cookie" 作为数组大小，导致乱序析构或访问非法内存。 (Программа попытается прочитать несуществующий "Cookie", что приведет к крашу или доступу к чужой памяти.) |
| `new T[10]`           | `delete p`              | **Memory Leak / UB**. 只有第一个元素被析构，剩余 9 个元素的析构函数不会被调用（导致资源泄漏），且内存释放可能出错（因为指针位置不对，忽略了 Cookie）。 (Будет разрушен только первый элемент. Деструкторы остальных 9 не вызовутся (утечка ресурсов), а освобождение памяти может сбиться из-за смещения на размер Cookie.) |

------

### 代码演示 (Демонстрация кода)

C++

```
#include <iostream>

class Widget {
public:
    Widget() { std::cout << "Construct\n"; }
    ~Widget() { std::cout << "Destruct\n"; }
};

int main() {
    std::cout << "--- Single Object ---\n";
    Widget* w = new Widget();
    delete w; 
    // 1. 调用 ~Widget()
    // 2. 调用 operator delete(w)
    // 1. Вызов ~Widget()
    // 2. Вызов operator delete(w)

    std::cout << "\n--- Array Object ---\n";
    Widget* wArr = new Widget[3];
    delete[] wArr;
    // 1. 读取 Cookie 发现大小为 3
    // 2. 调用 ~Widget() 3次 (通常是逆序)
    // 3. 调用 operator delete[](wArr)
    // 1. Читает Cookie, видит размер 3
    // 2. Вызывает ~Widget() 3 раза (обычно в обратном порядке)
    // 3. Вызывает operator delete[](wArr)

    return 0;
}
```

### 总结 (Резюме)

- **`delete`** = `Destructor` (x1) + `operator delete`
- **`delete[]`** = Read Size + `Destructor` (xN) + `operator delete[]`
